About the project

    

      

        
Most regex testers tell you whether a string matches and stop there. This platform shows why. It compiles your expression into the automata that decide the match (an NFA, then a DFA, then the smallest equivalent DFA) and lets you step through each test string one symbol at a time.

        
It is a Theory of Computation course project at Vellore Institute of Technology. The aim is to turn Thompson's Construction, Subset Construction and DFA minimization into something you can see and try, instead of something you only read about.

        
The NFA, DFA and minimal DFA were checked against a standard regex engine on every string up to length six for a set of sample expressions, the three minimization algorithms give identical results, and the generated strings always match.

      

      

        
How it works

        
    
          
  1. ParseA tokenizer splits the expression into tokens, then a recursive-descent parser builds the syntax tree. Errors are reported by position.
    2. 
          
  2. NFAThompson's Construction turns the tree into an NFA with ε-transitions.
    3. 
          
  3. DFASubset Construction removes the nondeterminism using ε-closures.
    4. 
          
  4. MinimizeHopcroft's algorithm merges states that behave identically. Table-filling and partition refinement are built in too, and all three give the same result.
    5. 
          
  5. ExplainEach string is traced step by step, with the reason it was accepted or rejected.
    6. 
          
  6. GenerateRandom walks on the minimal DFA produce strings that always match.
    7. 
          
  7. CompareTwo expressions are equivalent when their minimal DFAs accept the same strings. A search finds the shortest string that tells them apart.
